# 1 项目概述
## 1.1 项目背景
火电厂运维三大核心痛点：
1. DCS告警洪泛，单点阈值告警无趋势、跨设备关联分析，人工监盘压力大；
2. 故障处置依赖老师傅经验，历史缺陷台账与检修规程缺乏标准化检索（3200条五级结构缺陷FAQ、3份检修规程），新人上手慢；
3. 工作票/操作票人工填写易漏危险点、证件校验，存在安全生产隐患；
4. 故障处置经验无法自动沉淀，案例复用率低，无闭环学习机制。

基于一期单Agent私有化RAG知识库底座，搭建**事件驱动多Agent协同系统**，内网断网私有化部署，数据不出厂区，满足电力等保与安全生产管控要求。

## 1.2 项目核心目标
1. 设备24h智能感知：告警去抖、归并、趋势预警、跨测点关联分析，降低无效告警；
2. 多班组并行故障会诊：锅炉/汽机/电气/热控/燃除5类专家Agent协同输出结构化诊断；
3. 两票智能辅助审查：规则硬约束+LLM语义查漏，自动生成标准化票型草稿；
4. 人机分级协同：高风险节点强制人工确认，AI仅输出参考素材，不自主决策；
5. 知识自迭代闭环：人工复核后的故障案例自动增量入库，检索精准度持续提升。

## 1.3 核心设计原则（工业AI底线，面试高频口述点）
1. **无AI自主决策**：所有诊断、处置建议仅作为参考，最终操作、结论由人工确认；
2. **受控可编排**：基于LangGraph状态机强约束流程，禁止Agent自由发散执行；
3. **私有化合规**：全程断网运行，原始生产数据、模型、向量库全部本地存储；
4. **算力按需调度**：规则引擎24h常驻无LLM消耗，仅异常事件唤醒大模型推理；
5. **幻觉严格管控**：领域外问题100%拒答，所有结论必须绑定知识库原文来源；
6. **全程可审计**：TraceID全链路追踪，每一步Agent调用、人工操作留痕可溯源。

# 2 术语与定义
| 术语 | 释义 |
| ---- | ---- |
| DefectEvent | 标准化缺陷事件，监测Agent归并告警后生成，event_id全局唯一（TraceID） |
| interrupt | LangGraph人机中断节点，流程挂起等待人工确认，确认后恢复执行 |
| Send fan-out | LangGraph并行调度API，动态激活对应专业专家Agent并行会诊 |
| Checkpoint | 状态快照持久化，服务重启/人工长时间中断支持断点续跑 |
| 两票 | 工作票（设备检修作业）、操作票（设备启停/切换操作） |
| 知识闭环 | 故障处置复盘人工准入 → 案例结构化入库 → 向量增量追加检索库 |
| 混合检索 | BM25稀疏关键词检索+BGE-M3稠密向量检索，加权融合打分 |

# 3 用户角色与使用场景
## 3.1 角色清单
1. 运行值班员：监盘、确认设备告警诊断、审批处置方案（人工确认①/②）
2. 检修维护人员：执行消缺、复盘故障案例、提交入库审核（人工确认④）
3. 两票填票人：使用AI草稿辅助，核对安全措施、证件（人工确认③）
4. 知识库管理员：维护FAQ、检修规程、清理无命中问题池
5. 系统管理员：vLLM模型网关配置、评测回归、服务运维、日志排查

## 3.2 典型业务场景
场景1：DCS测点越限→监测Agent生成缺陷事件→多专家并行会诊→人工核实故障→生成处置方案；
场景2：需要停机检修→两票Agent生成草稿+安全规则校验→人工定稿走ERP开票；
场景3：故障处理完成→LLM自动生成复盘摘要→人工审核通过→案例增量入库。

# 4 功能需求 FR（按模块编号，P0必实现）
## FR-1 监测感知Agent模块（P0）
1. FR-1.1 24h常驻消费DCS测点数据流（生产OPC UA接口、演示本地模拟器）；
2. FR-1.2 内置规则引擎，支持阈值越限、滑动窗口趋势、变化率、跨测点组合异常判定；
3. FR-1.3 区分两类输出：趋势预警（仅提示，不触发诊断）、缺陷告警（进入会诊流程）；
4. FR-1.4 告警降噪：同设备同测点时间窗去抖；时间窗口+设备关联矩阵双条件归并连锁告警；
5. FR-1.5 告警按严重度分级调度：重大＞较大＞一般，高优先级优先进入会诊队列；
6. FR-1.6 输出标准化DefectEvent事件，携带event_id、设备编号、班组、时间线、异常描述。

## FR-2 LangGraph多Agent协同编排核心（P0）
1. FR-2.1 支持多节点状态机编排：START→诊断子图→四级人工中断→复盘入库→END；
2. FR-2.2 动态并行调度Send：根据设备归属，仅激活1~2个对应专业专家Agent，节省算力；
3. FR-2.3 内置条件边风险路由：区分低/中/高风险，低风险自动跳过人工确认，高风险每步强制中断；
4. FR-2.4 Checkpoint持久化：SqliteSaver存储全流程State，服务重启、人工小时级中断可断点续跑；
5. FR-2.5 全局共享结构化State：所有Agent仅读取自身所需局部视图，数据隔离防上下文爆炸；
6. FR-2.6 幂等执行防护：event_id作为唯一标识，重复触发复用已有结果，避免重复LLM调用。

## FR-3 五大专业化Agent能力需求（P0）
### FR-3.1 主控Orchestrator Agent（调度中枢）
- 动态路由分发缺陷事件至对应专业专家；
- 收集并行专家结构化研判意见，整合分歧清单、参考处置方案；
- 仅做信息汇总，不输出最终判定结论，分歧全部转交人工裁决。

### FR-3.2 班组专家Agent×5（锅炉/汽机/电气/热控/燃除）
- 内置混合检索链路：BM25+BGE-M3向量检索，可选BGE-Reranker重排；
- 输出结构化诊断结果：故障可能原因、现场验证步骤、设备影响、置信度、知识库原文来源；
- 边界约束：仅输出研判素材，不生成最终操作指令。

### FR-3.3 两票辅助Agent
- 硬编码规则校验：必填项、危险点三阶段覆盖、动火/受限空间证件校验；
- LLM语义查漏，识别漏项、不合规描述；
- 内置标准票型模板（磨煤机检修/一次风机振动/干渣机检修/汽机轴瓦/电气电机），生成检修草稿；
- 边界约束：不直接提交/签发ERP工单，仅辅助人工填写。

### FR-3.4 复盘Agent
- LLM自动生成标准化复盘摘要：故障现象、根因、处置方案、设备恢复标准；
- 结构化清洗案例数据，统一入库格式；
- 未通过人工审核的案例禁止写入知识库。

### FR-3.5 监测Agent（感知层）
见FR-1模块，负责测点消费、告警降噪、事件生成。

## FR-4 四级人机协同人工中断机制（P0，工业安全核心）
1. 确认①：现场核实故障诊断结果（高风险强制中断）；
2. 确认②：人工批准设备处置方案；
3. 确认③：两票草稿定稿，确认后人工自行走ERP开票；
4. 确认④：复盘案例准入审核，批准后方可增量入库；
- 分级策略：普通低风险缺陷自动放行，跳过全部人工节点；重大设备、动火、受限空间每一步强制人工确认。

## FR-5 知识闭环与知识库管理（P0）
1. FR-5.1 TraceID查重，完全相同故障事件禁止重复入库；
2. FR-5.2 案例清洗结构化，统一字段规范存入本地案例库；
3. FR-5.3 load_kb统一加载，新增案例实时纳入检索范围；
4. FR-5.4 向量库增量追加写入，幂等写入防止重复向量化；
5. FR-5.5 缓存一致性自检，规避全量重编码性能故障；
6. FR-5.6 知识库分层：基础FAQ、检修规程、增量复盘案例三库隔离。

## FR-6 接口层需求（FastAPI，P1）
1. FR-6.1 标准HTTP接口：/api/qa 故障问答、/api/review 两票审查；
2. FR-6.2 Pydantic Schema全量入参/出参校验，格式错误直接拦截，不进入LLM推理；
3. FR-6.3 统一异常封装，区分参数错误、服务500内部异常、503服务不可用，配套重试+降级策略。

## FR-7 可观测与审计需求（P0，电力等保强制）
1. FR-7.1 LangFuse全链路追踪，TraceID串联告警、检索、Agent调用、人工操作；
2. FR-7.2 结构化日志记录：调用时间、入参、返回内容、操作人、异常堆栈；
3. FR-7.3 失败案例台账自动归档，记录现象、根因、规避方案，用于迭代回归测试；
4. FR-7.4 检索来源强制留存，支持事后溯源核对规程原文。

# 5 非功能需求 NFR（工业场景硬性指标）
## 5.1 性能指标
1. 单条混合检索响应：缓存命中≤0.3s，全量检索≤1s；
2. 端到端故障会诊（1~2个专家并行）整体耗时≤24s；
3. 知识库增量入库单案例处理≤200ms；
4. 系统支持并发10条缺陷事件并行处理无阻塞。

## 5.2 安全合规（P0最高优先级）
1. 私有化断网部署，所有模型、业务数据、向量库本地存储，数据不出厂区；
2. 模型安全约束：领域外无关问题拒答率100%，无匹配知识库禁止编造内容；
3. 输出契约校验+硬规则双层防线，LLM输出必须经过业务规则过滤；
4. 所有人工操作、Agent调用永久日志留存，满足电力安全审计追溯；
5. 工具权限隔离：Agent仅拥有查询权限，无修改、删除生产数据权限。

## 5.3 可靠性
1. 服务崩溃、人工长时间中断，Checkpoint断点续跑，不丢失中间流程状态；
2. LLM服务503不可用时自动降级，返回标准化异常提示，不阻断业务；
3. 知识库损坏支持版本回滚，增量案例可批量删除恢复；
4. 全量单元测试32个用例、3套集成测试全覆盖。

## 5.4 可维护性
1. Agent模块化解耦，新增专业班组仅新增专家Agent，不改动核心编排逻辑；
2. 一键评测回归脚本，修改提示词、知识库后自动量化检索指标；
3. 分层日志分级输出，区分调试、业务、错误日志，方便线上排查；
4. 模型网关双模式切换：开发DeepSeek API、生产72B vLLM私有化，配置切换无需改业务代码。

## 5.5 算力约束
1. 监测规则引擎常驻无GPU消耗；
2. LLM推理按需唤醒，无告警事件不占用GPU算力；
3. vLLM支持AWQ 4bit量化，单GPU可承载72B大模型离线推理。

# 6 数据需求
1. 知识库原始数据：历史缺陷台账（脱敏模拟数据）清洗后沉淀**3200条五级结构缺陷FAQ**；检修规程 **3 份（锅炉检修/锅炉运行/设备安全）分块 360 块**；增量复盘案例持续沉淀；
2. 业务存储：SQLite/MySQL存储缺陷事件、两票草稿、复盘案例、审计日志；
3. 向量存储：本地向量库（演示numpy索引缓存/生产Milvus），存储FAQ、规程、复盘案例向量；
4. 时序数据：DCS测点流（生产OPC UA、演示模拟工况数据）；
5. 缓存数据：检索结果缓存、State状态快照、Checkpoint断点文件。

# 7 多Agent分工规范（面试高频提问：各个Agent职责与边界）
| Agent名称 | 核心输入 | 核心输出 | 职责范围 | 不可逾越红线 |
| --- | --- | --- | --- | --- |
| 监测Agent | DCS实时测点 | DefectEvent缺陷事件、趋势预警 | 24h数据消费、告警降噪、事件分级 | 不调用LLM、不做故障诊断 |
| 主控Orchestrator Agent | 缺陷事件、各专家意见 | 整合研判素材、分歧清单 | 路由分发、结果汇总 | 不自行推导故障结论、不给出处置方案 |
| 班组专家Agent | 缺陷事件、知识库向量库 | 结构化诊断（原因/验证/置信度/来源） | 检索资料、专业故障分析 | 不生成两票、不给出最终操作指令 |
| 两票辅助Agent | 故障处置方案、设备信息 | 标准化两票草稿、风险校验清单 | 票型生成、安全规则查漏 | 不提交ERP、不签发作业票 |
| 复盘Agent | 完整处置流程记录 | LLM复盘结构化摘要 | 案例清洗、格式化入库 | 无人工审核不写入知识库 |

# 8 系统部署形态
## 形态1：单机一体化（班组演示、小规模试点）
LangGraph编排、向量库、业务库、Web界面同机部署；vLLM推理网关外置GPU服务器。

## 形态2：正式生产拆分部署
1. vLLM 72B推理服务独立GPU服务器；
2. 向量库、业务数据库独立服务；
3. 业务编排服务单独部署，通过OPC UA对接厂区DCS；
4. 所有服务内网隔离，无外网访问权限。

# 9 验收标准（可量化，面试可直接背诵）
1. 检索评测指标：Top3召回率≥96%，Top5召回率100%；
2. 幻觉管控：领域外无关问题拒答率100%，知识库引用准确率100%；
3. 人机协同：重大高风险故障人工接管率100%，普通低风险缺陷自动放行率≥50%；
4. 业务闭环：告警→会诊→两票→人工确认→复盘入库端到端流程通过率≥90%；
5. 可靠性：服务重启后断点续跑成功率100%，无状态丢失；
6. 合规：完整审计日志留存，所有AI输出绑定知识库原文来源；
